# 変更履歴

ルールの変更を、新しい順に書く。取り込んだ側は、前回の取り込み以降の項目を読み、
「使っている側で直すこと」に従って手元の CSS や設計書を直す。

## 2026-11-21（2）

**変更**

- 3 節に、block は自分の大きさを固定の値で持たない、という決まりを足した。
  大きさは中身か親の並べ方で決め、その場所での幅は親が `__要素` クラスか layout で与える。
  文章の行の長さ（`max-inline-size`）も親が与える。
  block が自分で持ってよいのは、中身に比例する値、下限、親の並びの外に出る部品の幅、中身の大きさを持たない飾りの大きさだけ
- 「書き終えたら確認すること」に、同じ内容の確認を足した

**使っている側で直すこと**

- block に書いた固定の幅（`inline-size`、`max-inline-size` など）を洗い出す。
  その場所だけの幅なら、置かれた先の親の `__要素` クラスへ移す。繰り返し使う幅なら、layout にする
- 文章の部品（リード文、`.c-prose` など）に書いた行の長さの上限を外し、置かれた先の親で与える

## 2026-11-18

**変更**

- 7 節の `.c-prose` を書き直した
  - 見た目は、直下の子に限らず、子孫の要素に当てる
  - 文脈の余白は、直下の子に加えて、流れを作る入れ物（`blockquote`、`li`、`dd`）の子にも付ける。
    入れ物の中の先頭は `:where(:first-child)`（[0,1,0]）で打ち消す
  - `.c-prose` 自身には、継承されるプロパティを書かない
  - 余白をすべての子に付けて先頭を打ち消す理由（`* + *` にしない理由）と、通常のブロックの流れのまま使うことを足した
- 7 節に `.c-prose-end` を足した。prose の中に埋め込む部品を包むか、部品に mix し、
  中の要素への prose の指定を `all: revert-layer` で打ち消す
- 2 節の記述順に、`.c-prose` と `.c-prose-end` を components の先頭に置くことを足した
- 「書き終えたら確認すること」に、同じことを足した

**使っている側で直すこと**

- `.c-prose` を components の先頭に移し、その直後に `.c-prose-end`（`.c-prose-end :where(*) { all: revert-layer; }`）を足す
- `.c-prose` の見た目を `.c-prose > :where(…)` で書いていたら、`.c-prose :where(…)` にする。
  prose の中に部品を埋め込んでいる場所は、`.c-prose-end` で包むか、部品に mix する
- `.c-prose` の余白の指定に、入れ物の子の余白と、入れ物の中の先頭の打ち消しを足す
- `.c-prose` 自身に `color` や `line-height` などを書いていたら、子孫の要素に移す

## 2026-11-14（2）

**変更**

- 素の要素は外側の余白を持たない、と明記した（2・4・7 節）。
  ブラウザが既定で付ける `margin` は `reset` で 0 にし、`base` でも付けない。
  文脈の余白は `__要素` クラスで、クラスのない HTML には `.c-prose` で与える。
  これまでは 4 節の冒頭の前提が、既定の余白を残す読み方も許していた
- 「書き終えたら確認すること」と、ひな形の `global.css` のコメントに同じことを足した

**使っている側で直すこと**

- `reset` で、見出し・段落・リストなどの `margin` を 0 にする。`dialog` などの位置合わせの `auto` は残す
- `base` で素の要素に `margin` を付けていたら、消す
- 素の要素の余白に頼っていた場所は、`__要素` クラスで文脈の余白を与えるか、クラスのない HTML なら `.c-prose` で包む
- 余白が変わるので、ページごとに見た目を確かめる
